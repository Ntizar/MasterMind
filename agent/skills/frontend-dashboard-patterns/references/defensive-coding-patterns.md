# Defensive Coding Patterns — Fallbacks para datos incompletos

## El problema

En dashboards SPA con datos de encuestas, APIs y formularios, el `appState` a menudo está **parcialmente poblado**. Los módulos que procesan datos fallan con `Cannot read property of undefined` cuando esperan datos que aún no existen.

## Patrón 1 — Optional chaining en accesos anidados

```javascript
// ❌ Crash cuando indicadoresParked es undefined
if (indicadoresParked.consejo.includes('teletrabajo')) { ... }

// ✅ Optional chaining
if (indicadoresParked?.consejo?.includes('teletrabajo')) { ... }
```

**Cuándo usarlo:** En TODOS los accesos a objetos que vienen de datos de usuario/API que podrían no existir. Especialmente en callbacks y funciones que procesan encuestas.

## Patrón 2 — Fallback en parámetros de función

```javascript
// ❌ Fail cuando state.encuesta es undefined
function generarMedidas(state) {
    const respuestas = state.encuesta.respuestas; // TypeError
}

// ✅ Fallback en el parámetro
function generarMedidas(state) {
    const encuesta = state.encuesta || { agregados: {}, respuestas: [] };
    const respuestas = encuesta.respuestas;
}
```

## Patrón 3 — Defaults por defecto en objetivos/medidas

```javascript
// ❌ state.empresa puede no existir
const sector = state.empresa.sector;
const nombre = state.empresa.nombre;

// ✅ Defaults
const sector = state.empresa?.sector || 'servicios';
const nombre = state.empresa?.nombre || 'Empresa';
```

## Patrón 4 — Diagnóstico derivado cuando no hay encuesta

```javascript
// Cuando no hay datos de encuesta, derivar del employee list
function calcularDiagnostico(state) {
    if (state.encuesta?.agregados?.totalEncuestados > 0) {
        return calcularDesdeEncuesta(state);
    }

    // Fallback: derivar del listado de empleados
    const total = state.empleados?.length || 0;
    const teletrabajadores = state.empleados?.filter(e => e.teletrabajo !== 'nunca').length || 0;
    return {
        repartoModal: [
            { modo: 'coche_particular', count: Math.round(total * 0.8), percent: 80 },
            { modo: 'transporte_publico', count: Math.round(total * 0.12), percent: 12 },
            { modo: 'bicicleta', count: Math.round(total * 0.05), percent: 5 },
            { modo: 'a_pie', count: Math.round(total * 0.03), percent: 3 },
        ],
        // ...
    };
}
```

## Patrón 5 — Optional chaining enDAFO

```javascript
// El DAFO depende de indicadores calculados que pueden no existir
function calcularDAFO(state) {
    const indicadores = calcularIndicadoresParked(state);
    const fortalezas = [];

    if (indicadores?.consejo?.includes('teletrabajo')) {
        fortalezas.push('Política de teletrabajo existente');
    }
    if (indicadores?.nivelSostenibilidad === 'alto') {
        fortalezas.push('Buena cobertura de modos sostenibles');
    }
    // ...
}
```

## Patrón 6 — Dual data structure readers (demo vs production)

When demo/seed data uses a different field structure than production data, use nullish coalescing for fallback paths:

```javascript
// ❌ Hardcoded path — crashes if demo data uses different structure
const sostenible = state.diagnostico?.resumen?.porcentajeSostenible;
const co2 = state.diagnostico?.co2e?.totalToneladas;

// ✅ Dual fallback — supports both demo and production structures
const diag = state.diagnostico || {};
const res = diag.resumen || {};
const sostenible = res.porcentajeSostenible ?? diag.porcentajeSostenible ?? 0;
const co2 = diag.co2e?.totalToneladas ?? diag.huellaCO2e?.totalCo2eTon ?? 0;
```

**When to use:** Any time demo/seed data is generated by a different code path (e.g., a generator script) than the production data entry flow. The generator may nest fields differently.

## Regla general

**Cada función que accede a `state.*` debe usar optional chaining o defaults.** No asumas que el estado está completo. El flujo típico es:

1. Usuario rellena datos parciales
2. Se calcula diagnóstico (con fallbacks)
3. Se genera DAFO (con fallbacks)
4. Se generan medidas (con fallbacks)
5. Se genera informe (con fallbacks)

Si un paso falla, los siguientes deben seguir funcionando con datos parciales.
