# LoRA y PEFT — Fine-Tuning Eficiente de Modelos Grandes

## 1. Resumen Ejecutivo

**LoRA** (Low-Rank Adaptation) y el ecosistema **PEFT** (Parameter-Efficient Fine-Tuning) permiten adaptar modelos grandes (LLMs, Diffusion, etc.) fine-tuneando solo una fracción minúscula de parámetros — típicamente <1%. Esto hace posible entrenar LLMs de 7B+ en hardware consumer, con VRAM que baja de ~140GB a ~8-12GB.

El ecosistema PEFT de HuggingFace ha evolucionado desde LoRA simple a +30 métodos: DoRA, VeRA, AdaLoRA, BOFT, FourierFT, CorDA, PiSSA, OLoRA, EVA, y muchas variantes más.

## 2. Paper Original

**LoRA: Low-Rank Adaptation of Large Language Models**

- **arXiv:** 2106.09685 (Junio 2021)

- **Citations (est.):** 15,000+

## 3. Fundamentos Matemáticos

### 3.1. La Idea Central

En lugar de actualizar toda la matriz de pesos $W_0 \in \mathbb{R}^{m \times n}$ durante el fine-tuning, LoRA congela $W_0$ y approxima la actualización $\Delta W$ como un producto de dos matrices de bajo rango:

$$\Delta W = B A$$

donde $B \in \mathbb{R}^{m \times r}$, $A \in \mathbb{R}^{r \times n}$, y $r \ll \min(m, n)$.

La forward pass se convierte en:

$$h = W_0 x + \Delta W x = W_0 x + B A x$$

### 3.2. Scaling Factor

El scaling factor controla la magnitud de la adaptación:

```
scaling = lora_alpha / r    # LoRA original
scaling = lora_alpha / sqrt(r)  # Rank-Stabilized LoRA (RS-LoRA)
```

RS-LoRA (paper: https://arxiv.org/abs/2312.03732) demostró que usar $\sqrt{r}$ en lugar de $r$ como denominador mejora significativamente la convergencia y estabilidad.

### 3.3. Conteo de Parámetros

Para un modelo LLaMA-2 7B con hidden_size=4096:

| Método | Parámetros | % del total |
|--------|-----------|-------------|
| Full fine-tuning | ~14B | 100% |
| LoRA (r=8) | ~24M | ~0.17% |
| LoRA (r=16) | ~48M | ~0.34% |
| LoRA (r=64) | ~192M | ~1.37% |
| QLoRA (4-bit + r=16) | ~48M | ~0.34% |

### 4.1. Métodos Implementados

PEFT implementa +30 métodos de PEFT organizados en categorías:

#### Adaptadores de Matrices (Weight Decomposition)
- **LoRA** — Low-Rank Adaptation (el original)
- **DoRA** — Weight-Decomposed Low-Rank Adaptation (2024)
- **VeRA** — Vector-based Random Matrix Adaptation
- **AdaLoRA** — Adaptive Rank Allocation LoRA
- **OLoRA** — Outlier-aware LoRA
- **CorDA** — Correlation-based Decomposition Adaptation
- **EVA** — Eigenvector-based Adaptation
- **PiSSA** — Principal Singular Values and Singular Vectors Adaptation
- **LoFTQ** — LoRA with Fine-Tuning-free Quantization

#### Adaptadores Estructurales
- **IA³** — Infused Adapter by Inhibiting and Amplifying Inner Activations
- **Adapters** — Modular adapter layers (Houlsby et al.)
- **Adaption Prompt** — Para LLMs pre-entrenados

#### Prompt/Prefix Methods
- **P-Tuning v1/v2** — Soft prompt tuning
- **Prefix Tuning** — Soft prefix optimization
- **Prompt Tuning** — Solo embeddings entrenables
- **Multitask Prompt Tuning** — Para múltiples tareas

#### Métodos Avanzados
- **BOFT** — Basis Orthogonal Fourier Transform
- **FourierFT** — Frequency-domain adaptation
- **HRA** — Hierarchical Reparameterization Adaptation
- **Hira** — Hierarchical Rank Adaptation
- **LNTuning** — LayerNorm tuning
- **LoHa/LoKr** — Hadamard/Kronecker factored LoRA
- **aLoRA** — Asynchronous LoRA

### 4.2. LoraConfig — Parámetros Clave

```python
from peft import LoraConfig

config = LoraConfig(
    # Rank de adaptación (core)
    r=8,                          # Dimensión del espacio latente
    
    # Scaling
    lora_alpha=32,                # Alpha para scaling (alpha/r o alpha/sqrt(r))
    use_rslora=True,              # Usa sqrt(r) en lugar de r para scaling
    
    # Target modules
    target_modules=[             # Qué capas adaptar
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
        # "lm_head"  # Opcional: suele ser innecesario
    ],
    # O usar "all-linear" para adaptar TODAS las linear/Conv1D
    
    # Dropout
    lora_dropout=0.05,
    
    # Inicialización avanzada
    init_lora_weights="gaussian", # "gaussian", "pissa", "olora", "corda",
                                  # "loftq", "eva", "orthogonal", "True/False"
    
    # DoRA (descomposición de pesos)
    use_dora=False,               # Activar DoRA en lugar de LoRA estándar
    
    # Bias handling
    bias="none",                  # "none", "all", "lora_only"
    
    # Fan-in/fan-out (para Conv1D de GPT-2)
    fan_in_fan_out=False,
)
```

## 5. Implementación Práctica

### 5.1. Setup Básico con Transformers

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# 1. Cargar modelo base
model_name = "meta-llama/Llama-3.2-3B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    device_map="auto",
)

# 2. Configurar PEFT
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    init_lora_weights="gaussian",
)

# 3. Aplicar LoRA
model = get_peft_model(model, peft_config)
model.print_trainable_parameters()
# trainable params: 4,194,304 || all params: 3,211,235,840 || 0.13%

# Preparar para k-bit training
model = prepare_model_for_kbit_training(model)

# Ahora aplicar LoRA como antes
model = get_peft_model(model, peft_config)
```

### 5.3. DoRA — Weight-Decomposed LoRA

```python
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    use_dora=True,  # Activar DoRA
    init_lora_weights="pissa",  # PiSSA initialization funciona bien con DoRA
)
```

DoRA descompone los pesos en magnitud y dirección:
$$W = \|w\| \cdot \frac{w}{\|w\|} = \|w\| \cdot \hat{w}$$

Y aplica LoRA solo a la dirección normalizada $\hat{w}$, lo que estabiliza el training y mejora la calidad.

### 5.4. PiSSA — Inicialización Basada en SVD

```python
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    init_lora_weights="pissa",  # Principal SVD initialization
)
```

PiSSA inicializa las matrices LoRA usando los vectores singulares principales de la matriz de pesos original, en lugar de aleatorios. Esto da un punto de partida mucho mejor y acelera la convergencia.

### 5.5. Cargar y Usar un Adapter

```python
from peft import PeftModel, PeftConfig

# Cargar el modelo base
base_model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    device_map="auto",
)

# Cargar el adapter
config = PeftConfig.from_pretrained("./llama3-2-3b-lora-adapter")
model = PeftModel.from_pretrained(base_model, "./llama3-2-3b-lora-adapter")

# Inference
inputs = tokenizer("Hola, ¿cómo estás?", return_tensors="pt").to(model.device)
outputs = model.generate(**inputs, max_new_tokens=128)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))
```

### 5.6. Multi-Adapter y Switching Dinámico

```python
# Crear múltiples adapters para diferentes tareas
task1_config = LoraConfig(r=8, target_modules=["q_proj", "v_proj"], task_type="CAUSAL_LM")
task2_config = LoraConfig(r=8, target_modules=["k_proj", "o_proj"], task_type="CAUSAL_LM")

model.add_adapter("task1", task1_config)
model.add_adapter("task2", task2_config)

# Activar/desactivar adapters dinámicamente
model.set_active_adapter("task1")  # Solo task1 activo
outputs = model.generate(**inputs)

model.set_active_adapter("task2")  # Solo task2 activo
outputs = model.generate(**inputs)

# Combinar adapters (weighted)
model.set_adapter(["task1", "task2"])
```

## 6. Variantes Avanzadas

### 6.1. RS-LoRA (Rank-Stabilized)

```python
LoraConfig(
    r=16,
    lora_alpha=16,  # Con RS-LoRA, alpha=r es la configuración óptima
    use_rslora=True,  # Activa el scaling sqrt(r)
)
```

El scaling factor original `alpha/r` tiende a hacer que las actualizaciones de LoRA crezcan demasiado rápido. RS-LoRA usa `alpha/sqrt(r)` que mantiene las magnitudes más estables.

### 6.2. AdaLoRA

```python
from peft import AdaLoraConfig

config = AdaLoraConfig(
    init_r=12,           # Rank inicial
    target_r=4,          # Rank final objetivo
    tinit=500,           # Steps hasta rank mínimo
    tfinal=16000,        # Steps totales
    deltaT=500,          # Intervalo de ajuste de rank
    lora_alpha=32,
    lora_dropout=0.1,
    target_modules=["q_proj", "v_proj"],
)
```

AdaLoRA asigna ranks dinámicos a diferentes capas durante el training — más rank a las capas importantes, menos a las menos importantes.

### 6.3. VeRA (Vector-based Random Matrix Adaptation)

```python
from peft import VeRAConfig

config = VeRAConfig(
    init_mode="batch_average",  # O "random"
    scale=0.5,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)
```

VeRA usa matrices aleatorias fijas $A, B \in \mathbb{R}^{d \times k}$ y solo entrena dos vectores escalares $a, b \in \mathbb{R}^k$ por adapter. Esto reduce drásticamente los parámetros entrenables mientras mantiene el mismo VRAM de activation.

### 8.2. MicroVM Deployment

Con la MicroVM (1vCPU/2GB), el enfoque correcto es:
- **QLoRA 4-bit** para training (VRAM mínimo)
- **Merge weights** para inference (sin overhead de LoRA)
- **Modelo objetivo:** Llama-3.2-3B o Phi-3-mini (3.8B)

### 8.3. Conexión con Speculative Decoding

De la nota anterior:
- **Medusa heads** son esencialmente adapters — LoRA y Medusa son complementarios
- Un modelo fine-tuneado con LoRA puede luego usar speculative decoding para inference más rápida
- **SWIFT** (del paper anterior) puede extraer drafters del propio modelo LoRA

## 10. Lecciones Clave

1. **LoRA no es solo para LLMs.** Funciona con cualquier modelo con matrices de peso densas: Diffusion, Vision Transformers, etc.
2. **init_lora_weights importa más de lo que parece.** PiSSA y OLoRA dan resultados notablemente mejores que gaussian aleatorio, especialmente con ranks bajos.
3. **RS-LoRA es el nuevo estándar.** `use_rslora=True` con `lora_alpha=r` debería ser el default en 2026.
4. **DoRA mejora calidad sin overhead de inference.** A diferencia de LoRA, los pesos DoRA se pueden mergear completamente sin cambiar la inference.
5. **No necesitas adaptar todas las capas.** En transformers, adaptar solo attention (q/k/v/o) + feed-forward (gate/up/down) suele ser suficiente.
6. **LM head casi nunca necesita LoRA.** Es una de las capas más grandes pero aporta poco al fine-tuning.
7. **4-bit + LoRA es el sweet spot.** QLoRA con NF4 + double quantization ofrece el mejor ratio calidad/VRAM.
