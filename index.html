Decaimiento de Ebbinghaus

Los aprendizajes se cargan bajo demanda, filtrados por relevancia Y decaimiento temporal. Si R(t) > 0.3, se incluye. Si no, se omite. Tu contexto siempre está optimizado.

R(t) = a / (log(t+1))b + c
Características

Memoria Persistente

Cada sesión archiva aprendizajes con metadatos de decaimiento. La siguiente empieza más inteligente.

Multi-Modelo

Opus para el crítico. Flash para sintetizar. Gemini para explorar. Cada agente usa el mejor modelo para su rol.

Crítico Adversarial

Nunca se degrada. Si no puede ejecutar, omite. La calidad no es negociable.

📊

3 Niveles Adaptativos

Tareas simples: 2 agentes. Medias: 3-4. Complejas: 5+ con flujo completo. Sin sobrecostes.

🎯

Human-in-the-Loop

Checkpoints obligatorios. La IA propone modelos, el humano confirma. Tú decides la arquitectura.

12 Reglas

Derivadas de 13 ciclos de uso real

  1. Flujo completo obligatorio — ningún agente se salta
  2. Sincronización multi-archivo — propagar cambios a todos los archivos afectados
  3. Verificar integridad binaria — magic bytes, no solo extensiones
  4. Deploy consciente de la plataforma — conocer las limitaciones del hosting
  5. README actualizado con cada versión — siempre al día
  6. El humano decide la arquitectura — la IA propone, el humano dispone
  7. Clusters dinámicos — las categorías de conocimiento crecen orgánicamente
  8. Carga bajo demanda — aprendizajes por relevancia + decaimiento
  9. Capacidad mínima documentada — cada agente tiene un suelo
  10. Crítico: omitir, nunca degradar — la calidad no es negociable
  11. Verificar en vivo antes de entregar — confirmar que el deploy funciona
  12. Asignación de modelos es colaborativa — el sistema propone, el humano confirma
