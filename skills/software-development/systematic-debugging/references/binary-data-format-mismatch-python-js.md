# Binary Data Format Mismatch — Python→JS Case Study (ISOTime, 2026-07-01)

## Bug Summary

ISOTime's Dijkstra Web Worker loads binary graph files (`.bin`) generated by Python's `generar-grafos.py`. The graph loads successfully (correct node count, no 404), but Dijkstra returns "Muy pocos nodos alcanzables" for every query.

## Root Cause

Python writes coordinates as **two separate contiguous arrays**:
```python
node_lats.tofile(f)  # bytes 64..64+N*4: [lat0, lat1, ..., latN]
node_lngs.tofile(f)  # bytes 64+N*4..64+N*8: [lng0, lng1, ..., lngN]
```

JavaScript reads them as **one interleaved array** via zero-copy view:
```javascript
const nodeCoords = new Float32Array(buffer, 64, numNodes * 2);
// Interprets bytes as: [lat0, lng0, lat1, lng1, ...]
// But actual layout is: [lat0, lat1, ..., latN, lng0, lng1, ..., lngN]
```

Result: `nodeCoords[0]` = lat0 (correct by coincidence), `nodeCoords[1]` = lat1 (should be lng0), `nodeCoords[2]` = lat2 (should be lat1), etc. Every coordinate pair after the first is wrong.

## Why It Was Hard to Debug

1. **No error thrown** — TypedArray view creation succeeds, no bounds error
2. **Graph loads correctly** — Node count matches, file size matches, no 404
3. **findNearestNode runs** — Returns a node index (the "nearest" is wrong but doesn't crash)
4. **Dijkstra runs** — Traverses edges, but coordinate comparisons are garbage
5. **Error message misleading** — "Muy pocos nodos alcanzables" suggests a graph coverage issue, not a format issue
6. **Debug messages invisible** — Worker's `postMessage({cmd:'debug'})` wasn't handled by the app's message handler, so intermediate state was lost

## Debugging Path (what worked)

1. Created standalone Worker instance in browser console
2. Listened to ALL messages with `w.onmessage = (e) => msgs.push(JSON.stringify(e.data))`
3. Loaded graph, sent isochrone request, observed error in messages array
4. Still couldn't see internal state → added enhanced error message with `originLat, originLng, originNode, reachable.length`
5. Error showed coordinates were wrong → compared with Python output → format mismatch

## Fix

```javascript
// Read separate arrays and interleave
const rawLats = new Float32Array(buffer, latOffset, numNodes);
const rawLngs = new Float32Array(buffer, lngOffset, numNodes);
const nodeCoords = new Float32Array(numNodes * 2);
for (let i = 0; i < numNodes; i++) {
  nodeCoords[i * 2] = rawLats[i];
  nodeCoords[i * 2 + 1] = rawLngs[i];
}
```

## Verification

Quick check after fix:
- Walking Madrid 30min → 7.1 km², 2.3km radio (1247 reachable nodes) ✓
- Car Madrid 15min → 356 km², 13.7km radio (32302 reachable nodes) ✓

## Related Issues Found During Same Debugging Session

1. **Physical distance filter missing** — Without `maxPhysicalDist`, car-mode Dijkstra at 120km/h follows highway edges across Europe → 9M km² polygon
2. **Web Worker path resolution** — Worker in `js/` couldn't find `data/graphs/` relative to page root → 404
3. **heap.pop() destructuring** — `{node, d}` instead of `{node, dist: d}` → `d` always undefined → cutoff never triggers

All three were fixed in the same session but were separate bugs from the format mismatch.
